# Disciplinary Rules for Project Development

## Rule 1: No Project Jumping
**CRITICAL**: When working on a specific project, you MUST complete comprehensive work on that project before moving to any other project. 

- If user says "work on X for few hours", you work ONLY on X until explicitly told to move
- No switching between projects within the same session without explicit user permission
- Complete all aspects of current project (frontend, backend, contracts, testing) before considering others

## Rule 2: Deep Focus Protocol
- Work on ONE project at a time with full attention
- Complete all identified issues and improvements for current project
- Test thoroughly before declaring project work complete
- Get explicit confirmation before moving to next project

## Rule 3: Documentation and Testing Priority
- Always test implementations thoroughly
- Update documentation as you work
- Ensure all components are functional before proceeding

## Rule 4: User Instruction Compliance
- Follow explicit timing instructions ("few hours", "complete this first")
- Do not interpret vague instructions as permission to switch projects
- Ask for clarification if unsure about project priority

**Violation of Rule 1 will result in disciplinary action**
